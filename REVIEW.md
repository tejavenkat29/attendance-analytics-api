# REVIEW.md

Defects found in the starter `app/main.py`. Line numbers refer to the original starter file.

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health` (L72) | Returns `{"status":"ok"}` unconditionally; never talks to MongoDB. Contract: 200 only if Mongo answers a ping, else 503. | Stop MongoDB, `GET /health` still says 200 while every data endpoint 500s. | `db.command("ping")` in try/except; `PyMongoError` → 503. |
| 2 | startup (whole file) | No indexes are ever created. The contract requires them at startup, idempotently; uniqueness guarantees and 100k-scale performance depend on them. | `db.attendance_logs.getIndexes()` shows only `_id`; explain shows COLLSCAN; duplicate emp_codes possible under load. | `create_indexes()` in the FastAPI lifespan: unique `employees.emp_code`, unique `(emp_code, date)` on logs, `(date desc, emp_code)` on logs, plus employees `(department, emp_code)`, `(department, joined_on)`, `(joined_on)`. |
| 3 | `compute_late_minutes` (L36-37) | Grace check happens after flooring: `int(610s/60)=10`, `10 > 10` is false. R2 says 09:40:01 → 10 late minutes; starter returns 0 for the whole 09:40:01–09:40:59 band. | Punch in at `shift_start + 10:01`; expect `late_minutes=10`, got 0. | Compare raw seconds (`> 600`), then floor minutes from shift start. |
| 4 | `compute_late_minutes` (L35) | Builds shift start with `punch_in.replace(hour=...)`: mixes zones (punch_in is UTC, shift is IST — 09:35 IST is 04:05 UTC, so "09:30" lands at 15:00 IST) and ignores that an overnight shift starts on the previous calendar day. | 09:35 IST punch-in against a 09:30 shift returns a huge negative/zero instead of 0; any overnight-shift punch-in is garbage. | Build the shift-start datetime explicitly on the attendance date with `tzinfo=IST`. |
| 5 | `compute_work_hours` (L41) | `round()` is banker's rounding (half-even); R4 demands half-up. | 4h27m54s = 4.465 h → starter 4.46, contract 4.47. Can flip `half_day` at the 4.495 boundary. | `Decimal(...).quantize(Decimal("0.01"), ROUND_HALF_UP)`. |
| 6 | `compute_overtime` (L44-47) | Three problems: missing the ≥30-minute threshold (R3), subtracts a tz-aware `end` from a naive `punch_out` (TypeError → 500), and for an overnight shift the shift end falls on the *next* day (not handled). | Sample doc #1: 5 min past shift end must give 0, starter gives 5 — if it doesn't crash first. | Shift-end built on the attendance date (+1 day when overnight), aware-vs-aware arithmetic, `minutes if minutes >= 30 else 0`. |
| 7 | `create_employee` (L79) | Check-then-insert: two concurrent creates both pass `find_one`, both insert → two 201s and duplicate emp_codes. Contract explicitly requires a database unique index. | Fire 2 parallel identical POSTs; both return 201. | Unique index on `emp_code`; `insert_one` and catch `DuplicateKeyError` → 409. |
| 8 | `EmployeeIn` model (L53-60) | No validation at all: any emp_code format, invalid emails, malformed shift strings, `shift_start == shift_end`, impossible `joined_on` all accepted. | POST `emp_code="x"`, `email="nope"`, `shift_start="99:99"` → 201. | Pydantic constraints matching the OpenAPI schemas + explicit `shift_start != shift_end` check (422). |
| 9 | `create_employee` (L82) | `datetime.now()` is naive server-local time: the stored instant is wrong unless the server runs UTC; response then leaks it as an ISO string instead of epoch ms. | Run with `TZ=Asia/Kolkata`; stored `created_at` is 5:30 off. Response shows `"2026-02-01T04:31:00"` instead of an integer. | Aware `datetime.now(timezone.utc)`; serializer converts every instant to epoch ms. |
| 10 | `list_employees` (L93) | `skip = page * page_size` — off by one page: page 1 starts at document `page_size`. | Seed 6 employees, `?page=1&page_size=3` returns EMP0004-0006. | `skip = (page - 1) * page_size`. |
| 11 | `list_employees` (L94) | `total = count_documents({})` ignores the department filter (R10: total reflects the filters); results are not sorted by `emp_code`; `page=0` produces a negative skip (PyMongo raises → 500); `page_size` is unbounded. | `?department=Sales` shows `total` = whole collection; `?page=0` → 500. | Count with the same query; `.sort("emp_code")`; `Query(ge=1)` / `Query(ge=1, le=100)` → 422. |
| 12 | `punch_in` (L101-102) | Unknown employee: `emp` is `None`, then `emp["shift_start"]` → TypeError → 500. Contract: 404. A 500 is always a failed test. | POST with a made-up emp_code. | Explicit `if emp is None: 404` before anything else. |
| 13 | `punch_in` (L102-103) | `datetime.fromtimestamp(ms/1000)` is naive server-local; `.date()` is then the server's calendar date, not the IST attendance date (R1). No overnight-shift rule, no truncation to whole seconds, naive datetime stored. | Punch at 01:00 IST: on a UTC server the record lands on the previous date; overnight-shift punch-ins land on the wrong day; `09:40:00.900` is not truncated. | `ms_to_dt()` truncates to seconds and converts UTC-aware; `attendance_date()` implements R1 incl. the overnight rule. |
| 14 | `punch_in` (L104) | Check-then-insert again: two simultaneous punch-ins both pass `find_one` → two 201s and two documents for the same (emp_code, date). | 6 parallel identical punch-ins: expect one 201 + five 409, got six 201s. | Unique compound index `(emp_code, date)`; catch `DuplicateKeyError` → 409. |
| 15 | `PunchInIn` model (L63-66) | `status` accepts any string (`ABSENT`, `"lol"` → 201); contract allows only PRESENT/WFH/ON_DUTY here. `punched_at` accepts seconds-looking values, floats and numeric strings — a seconds timestamp silently creates a record in 1970 instead of 422. | POST `status="ABSENT"` or `punched_at=1783312500`. | `Literal["PRESENT","WFH","ON_DUTY"]`; strict int field with the contract's min/max bounds. |
| 16 | `punch_in` / `list_attendance` (L119, L149) | Responses add an `id` built from `_id`. Contract: records have no id at all; `_id` never appears in a response. Punch datetimes also returned raw instead of epoch ms. | Compare any response against `AttendanceRecord` in openapi.yaml. | One serializer (`attendance_out`) producing exactly the contract shape. |
| 17 | `list_attendance` (L144-147) | Loads the entire filtered collection into Python, sorts and slices in memory — O(collection) per request at 100k docs; contract forbids this. Secondary sort by `emp_code` missing; no 422 when `date_from > date_to`; legacy docs missing `half_day`/`history` are returned without defaults. | Latency grows with collection size; two records on the same date come back in random order; range checks pass silently. | Mongo-side `.sort([("date",-1),("emp_code",1)]).skip().limit()` backed by the `(date, emp_code)` index; explicit 422; serializer fills defaults. |
| 18 | module level (L22) | `MongoClient` created without `tz_aware=True` (reads give naive datetimes — easy to corrupt arithmetic) and without `serverSelectionTimeoutMS` (a dead Mongo blocks the first call ~30 s, so /health could hang past the grader's 20 s readiness window). | Read any seeded doc: `punch_in.tzinfo is None`. Stop Mongo: /health hangs ~30 s. | `tz_aware=True, serverSelectionTimeoutMS=5000, connectTimeoutMS=5000`. |

## Looked at and decided it was fine

* **`load_dotenv()` without `override`** — correct: by default it does *not* override real environment variables, which is exactly what the contract asks (grader-injected env wins over a local `.env`).
* **Storing `date` as a `"YYYY-MM-DD"` string** — intentional per DATA_MODEL.md: a calendar date is not an instant; ISO strings compare correctly for ranges and sorting.
* **One module-level `MongoClient`** — PyMongo clients are thread-safe and pool connections; creating one per request would be the bug.
* **`history: []` initialised at punch-in** — correct: punch-in/out never write history; an uncorrected record has an empty list.
